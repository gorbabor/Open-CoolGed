Restreindre l'accès à un espace partagé

Guide administrateur — Open-CoolGed (ex-Kaeged GED) — état au 04/09/2026. Complète la fiche spec/profils-acces.html §6 et s'appuie sur le RBAC scopé existant (refus explicites par espace, deny prioritaire — écart n°35).

1. Objectif

Dans la GED, l'écran Documents regroupe les espaces partagés. Par défaut, un utilisateur voit les documents des espaces partagés selon son rôle (ex. rôle user : vue « tenant »). Besoin fréquent : qu'une série de documents d'un espace ne soit visible que par une partie des personnes, les autres ne voyant ni la liste, ni les fiches, ni les aperçus, ni les téléchargements de cet espace — sans toucher au reste de la GED.

Le moteur de permissions le permet sans développement, depuis l'interface d'administration, grâce à deux mécanismes existants :

  • Portée par espace : une permission peut être accordée ou refusée sur un espace précis plutôt que sur tout le tenant ;
  • Refus explicite prioritaire : un refus scopé sur l'espace l'emporte sur l'autorisation globale du rôle habituel (chaîne d'évaluation document → dossier → espace → tenant ; un refus ne peut être contourné, même par un partage).

2. Stratégie recommandée : « exclusion » (petit groupe à écarter)

À utiliser quand la majorité doit voir l'espace et qu'une minorité doit en être exclue.

Étape 1 — Créer le groupe d'exclusion
Menu Administration → Groupes → Nouveau groupe : ex. « Exclus Espace RH ». (Un groupe existant peut être réutilisé, ex. un service tiers.)
Étape 2 — Créer le rôle de restriction
Menu Administration → Rôles & permissions → Créer un rôle : ex. « Restriction RH ». Astuce : dupliquer un rôle existant puis retirer tous les droits, ou créer un rôle vide.
Étape 3 — Poser les refus scopés sur l'espace
Ouvrir le rôle → tableau des permissions → pour chacune des lignes ci-dessous :
Permission (slug)PortéeScopeRefus explicite
documents.view (voir)Espace« Espace : RH »coché
documents.preview (aperçu)Espace« Espace : RH »coché
documents.download (téléchargement)Espace« Espace : RH »coché
Optionnel : documents.comment, documents.share, documents.edit…Espace« Espace : RH »coché
Puis Enregistrer les permissions.
Étape 4 — Attacher le rôle au groupe
Administration → Groupes → « Exclus Espace RH » → Rôles du groupe (hérités par les membres) : cocher « Restriction RH » et enregistrer.
Étape 5 — Ajouter les personnes au groupe
Administration → Utilisateurs → Modifier → Groupes : ajouter chaque personne concernée au groupe « Exclus Espace RH ». Chaque personne cumule son rôle habituel + ce rôle de groupe : le refus scopé gagne (RM-008).
Effet attendu :
  • Les personnes exclues ne voient plus aucun document de l'espace RH dans Documents (ni fiche — 403 —, ni aperçu, ni téléchargement) ;
  • Leurs autres espaces restent inchangés ;
  • Les autres utilisateurs (sans le rôle de restriction) voient tout normalement ;
  • L'admin tenant et le super admin conservent la supervision (passe-partout).

3. Vérification

  1. Se connecter avec un compte d'une personne exclue : l'espace RH n'apparaît plus dans Documents (ni dans les filtres d'espace) ;
  2. Tenter l'URL directe d'un document de l'espace → page 403 ;
  3. Se connecter avec un compte non exclu : l'espace RH et ses documents restent visibles ;
  4. Consulter Administration → Utilisateurs → Permissions effectives du compte exclu : la colonne liste les permissions réelles (le refus y apparaît via le rôle de groupe).

4. Stratégie alternative : « audience » (si la majorité ne doit PAS voir)

Quand seuls quelques profils doivent accéder à l'espace :

  1. Créer des rôles métier étroits (sans le rôle user global) et des groupes d'audience ;
  2. Poser des permissions autorisées (refus décoché) avec Portée = Espace sur les seuls espaces concernés (documents.view/preview/download…) ;
  3. Attribuer ces rôles aux comptes concernés (rôle direct ou via groupe).
Ne pas donner le rôle user global à ces comptes : sa vue « tenant » leur redonnerait accès à tous les espaces. Cette stratégie se gère dès la création des comptes.

5. Cas particuliers et limites

  • Un document unique : l'UI ne propose que la portée espace (ou tenant). Pour restreindre un document isolé, utiliser le partage ciblé (positif, onglet Partage de la fiche) ; les portées dossier/document existent dans le modèle mais ne sont pas sélectionnables dans l'interface.
  • Refus vs partage : un refus explicite l'emporte sur tout — même un partage reçu ne redonne pas l'accès à une personne exclue.
  • Confidentialité (public/interne/confidentiel/secret) : attribut de qualification et de filtre, pas un verrou d'accès — seul le RBAC fait foi.
  • Cumul d'exclusions : une permission ne porte qu'un refus par rôle et par espace ; pour exclure de plusieurs espaces (RH et Finances), multiplier les groupes/rôles (ex. « Restriction RH », « Restriction Finances »).
  • Espaces personnels : non concernés (isolation propriétaire) ; les documents personnels restent visibles de leur propriétaire (supervision admin configurable).
  • Accès directs (URL) : liste, fiche, aperçu, téléchargement et visionneuses sont tous gardés côté serveur — le masquage de l'UI n'est pas le seul rempart.
  • Rôles système : non modifiables directement ; dupliquer le rôle puis appliquer la procédure sur la copie.

6. Rappels utiles

QuestionRéponse
Qui peut créer les groupes/rôles/refus ?L'admin tenant (permissions admin.groups, admin.roles) ; le super admin passe-partout.
La modification est-elle auditable ?Oui : création/édition de groupes, de rôles et d'affectations enregistrées dans le journal d'audit (écran Audit).
Effet immédiat ?Oui — les permissions sont évaluées à chaque requête, aucune déconnexion nécessaire.
Et « Mes documents » (V02) ?La vue opérationnelle ne montre que les documents approuvés applicables au périmètre de l'utilisateur : une personne exclue d'un espace n'y verra pas davantage les documents de cet espace.
