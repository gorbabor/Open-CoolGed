Documentation administrateur — Open-CoolGed (ex-Kaeged GED)

Guide complet des fonctionnalités d'administration de la plateforme : utilisateurs, groupes, rôles et permissions, types et métadonnées, référentiels V02, workflows, audit, paramètres, partage externe et super administration.

Application : votre URL d'installation (ex. https://votre-domaine). Comptes du seeder de démonstration (démonstration locale uniquement — à changer en production) : admin tenant admin@demo.local / password123 — super admin superadmin@kaeged.local / superadmin123

1. Introduction

Le menu Administration (sidebar) donne accès à 6 écrans :

ÉcranRôle
UtilisateursGérer les comptes, rôles directs, dimensions, suspension
GroupesRegrouper des utilisateurs et leur attacher des rôles (héritage)
Rôles & permissionsDéfinir les droits (catalogue de permissions, portées, refus)
Types & métadonnéesTypes documentaires et champs de métadonnées
RéférentielsDomaines, processus, postes, sites, entités, pays (périmètre V02)
AuditJournal des actions sensibles, filtres, export CSV

Le sous-menu Administration se déplie au clic et reste ouvert quand on est dans une page admin. Le super administrateur dispose d'un écran séparé « Super Admin → Paramètres plateforme ».

2. Utilisateurs

2.1 Créer un utilisateur

  1. Administration → Utilisateurs → formulaire « Créer un utilisateur »
  2. Nom, email, rôle (obligatoire), mot de passe (optionnel — généré sinon)
  3. « Créer » → l'utilisateur est actif ; le quota d'utilisateurs est vérifié (message d'erreur si atteint)
La longueur minimale du mot de passe est celle définie dans Paramètres → Sécurité (défaut 8 caractères).

2.2 Modifier un utilisateur

Bouton Modifier sur la ligne : nom, email, rôle, groupes (multi-sélection).

2.3 Réinitialiser le mot de passe

Bouton MDP → saisir le nouveau mot de passe (min. selon politique).

2.4 Suspendre / réactiver

Bouton Suspendre / Réactiver : l'utilisateur suspendu ne peut plus se connecter ni accéder aux ressources (vérifié à chaque requête).

2.5 Supprimer (logique)

Bouton Suppr. : suppression logique (RM-010) — l'historique, les versions et l'audit restent intacts. Un utilisateur ne peut pas se supprimer lui-même.

2.6 Dimensions organisationnelles (périmètre V02)

Dans la modale « Modifier » : poste, département, direction, site, entité, pays (listes issues des Référentiels). Ces dimensions pilotent le menu « Mes documents ».

2.7 Colonne « Permissions effectives »

Affiche l'union des permissions des rôles directs et des rôles hérités des groupes (badges + tooltip complet + compteur).

3. Groupes

3.1 Créer un groupe

Administration → Groupes → saisir le nom → « Créer ».

3.2 Gérer les membres

Chaque groupe affiche la liste des utilisateurs (sélection multiple) → « Mettre à jour ». Un utilisateur peut appartenir à plusieurs groupes. La suppression d'un groupe ne supprime jamais ses utilisateurs.

3.3 Rôles du groupe (héritage)

Section « Rôles du groupe (hérités par les membres) » : cocher un ou plusieurs rôles → « Enregistrer les rôles ». Tous les membres héritent immédiatement de ces rôles (en plus de leurs rôles directs).

Exemple : le groupe « Direction » avec les rôles « Manager » + « Validateur » donne à tous ses membres les permissions de ces deux rôles.

3.4 Renommer / supprimer

Boutons « Renommer » (modale) et « Supprimer » (confirmation demandée).

4. Rôles & permissions

4.1 Rôles système prédéfinis

RôleUsage
tenant_adminAdministrateur du tenant (toutes les permissions admin)
managerResponsable de périmètre (documents + workflow + IA)
userUtilisateur opérationnel standard
auditorAuditeur (lecture + accès au journal)
validatorValidateur de workflow

4.2 Créer / renommer / dupliquer / supprimer un rôle

  • Créer : formulaire en haut de l'écran
  • Renommer : bouton sur le rôle (rôles système non renommables)
  • Dupliquer : copie du rôle avec ses permissions (pour créer une variante)
  • Supprimer : bloqué pour un rôle système ou un rôle affecté à des utilisateurs

4.3 Catalogue de permissions

GroupePermissions
Documentsview, preview, download, create, edit, delete, restore, archive, comment, share, metadata
Workflowvalidate, approve, reject, manage
IAuse, admin
Administrationusers, groups, roles, types, workflows, audit, settings, quotas

4.4 Portées et refus explicite

Pour chaque permission : choisir la portée (tenant / espace / dossier / document) et un identifiant de portée. Cocher « Refus explicite » pour bloquer la permission sur ce périmètre.

Règle RM-008 : un refus explicite prévaut toujours sur une autorisation héritée ou directe — même si le même utilisateur a la permission via un autre rôle.
Exemple : refuser documents.download avec portée « espace RH » → personne avec ce rôle ne peut télécharger dans l'espace RH, même si le rôle autorise le téléchargement ailleurs.

5. Types & métadonnées

5.1 Types documentaires

  • Créer : nom + rétention (jours, vide = illimité)
  • Modifier : nom, rétention (modale)
  • Supprimer : bloqué si des documents utilisent le type

Les 15 familles V02 sont pré-créées : POL, MAN, REF, PRO, PRC, INS, FOR, REG, MOD, RAP, PRE, MAT, TDB, CHK, AUT.

5.2 Champs de métadonnées

Type de champUsage

Modifier / Supprimer : boutons sur chaque champ. La suppression est bloquée si des valeurs existent pour ce champ.

7. Workflows

7.1 Créer un workflow

  1. Menu Workflows → « Nouveau workflow »
  2. Nom + type documentaire associé (optionnel)
  3. Ajouter les étapes : nom + type d'assignation (utilisateur / groupe / rôle / créateur) + ID de l'assigné
  4. « Créer le workflow » — il est actif par défaut

7.2 Activer / désactiver

Bouton sur chaque workflow (les workflows inactifs ne peuvent pas être démarrés).

7.3 Déroulement

Depuis la fiche document (onglet Workflow) : « Démarrer le workflow » → le document passe « en revue », des tâches sont créées pour les assignés (visibles dans « Mes tâches »).

  • Valider : passe à l'étape suivante ; dernière étape → « approuvé »
  • Rejeter : motif obligatoire → retour brouillon + notification au créateur
  • Une tâche ne peut être traitée que par son assigné (ou délégataire)
  • Chaque décision est horodatée, attribuée et auditée

7.4 Périmètre V02 (règles d'approbation)

Avant le statut « approuvé/applicable », le système vérifie : fichier attaché, version renseignée, propriétaire affecté, date d'application, prochaine date de revue. Une nouvelle version applicable rend l'ancienne obsolète automatiquement.

8. Audit

8.1 Consultation

Administration → Audit : journal des actions sensibles (connexions, documents, versions, partages, droits, workflows, IA, actions admin). Filtres : action (texte), utilisateur, dates de début et fin.

8.2 Export CSV

Bouton « Exporter CSV » : télécharge le journal filtré (max 10 000 lignes) avec Date, Utilisateur, Action, Ressource, Détails, IP.

Le journal n'est pas modifiable via l'interface (table sans updated_at).

9. Paramètres

Administration → Paramètres : 9 onglets.

9.1 Général

  • Quotas : stockage (Mo), utilisateurs, taille max de fichier (Mo) — appliqués
  • Langue (fr/en) et fuseau horaire (ex. Europe/Paris)

9.2 Sécurité

  • MFA obligatoire pour administrateurs / validateurs — configurable seulement (application V2)
  • Expiration de session (minutes) — V2
  • Longueur minimale du mot de passe — appliquée immédiatement

9.3 Documents

  • Formats autorisés à l'import (cases MIME) — appliqués immédiatement
  • Verrouillage auto à l'édition — appliqué
  • Commentaire de version obligatoire — appliqué

9.4 Rétention

Durée par défaut (jours), purge de la corbeille après N jours, alerte avant suppression.

9.5 Notifications

Défauts : tâches (workflows), partages, échéances, notifications par email (SMTP requis).

9.6 Partage

  • Liens externes autorisés — appliqué (désactivé par défaut)
  • Durée maximale d'un lien (jours), mot de passe requis (optionnel/obligatoire)

9.7 IA

Activation IA du tenant + fournisseurs autorisés (séparés par virgules).

9.8 Workflows

Workflow par défaut (utilisé au démarrage manuel).

9.9 Branding

Couleur principale (appliquée via variables CSS : sidebar, boutons, barres) + logo (URL).

Chaque onglet est enregistré avec le bouton « Enregistrer les paramètres » ; toutes les actions sont auditées (admin.settings.updated, admin.branding.updated).

10. Partage externe

10.1 Principe

Les documents peuvent être partagés en interne (utilisateurs/groupes du tenant) ou via un lien externe (si activé dans Paramètres → Partage).

10.2 Créer un lien externe

  1. Fiche document → onglet Partage → section « Lien externe »
  2. Droit (consultation ou téléchargement), expiration obligatoire, mot de passe optionnel
  3. « Créer le lien » → le lien sécurisé s'affiche (à copier)

10.3 Sécurité

  • Accès par jeton aléatoire 256 bits stocké haché — jamais d'URL publique (RM-012)
  • Expiration maximale limitée par la politique du tenant
  • Révocable à tout moment (bouton « Révoquer »)
  • Chaque consultation/téléchargement est audité

11. Super administration

Accès réservé au super administrateur (superadmin@kaeged.local).

11.1 Statistiques globales

Nombre de tenants, utilisateurs, documents, stockage total.

11.2 Gestion des tenants

  • Créer un tenant (nom, plan, quotas) — les rôles système sont créés automatiquement et les paramètres plateforme sont appliqués en défauts
  • Admin initial (optionnel) : lors de la création, saisir nom, email et mot de passe (≥ 10 caractères) de l'administrateur de l'entreprise — le compte est créé avec le rôle tenant_admin du tenant et peut se connecter immédiatement. Sans admin fourni, le tenant est créé seul (aucun utilisateur)
  • Créer un admin pour un tenant existant : bouton « Créer un admin » sur la ligne du tenant dans la liste — même effet (compte + rôle tenant_admin)
  • Suspendre / réactiver : un tenant suspendu bloque toute connexion de ses utilisateurs (CA-017)
Le lien « compte admin ↔ entreprise » est porté par users.tenant_id + la relation user_role (rôle tenant_admin). Chaque création d'admin est auditée (superadmin.tenant_admin.created).

11.3 Paramètres plateforme

Défauts appliqués aux nouveaux tenants : sécurité (MFA, mot de passe), documents (MIME, verrouillage, commentaire), partage externe, IA. Les tenants existants ne sont pas modifiés.

11.4 Créer un super administrateur

Nom, email, mot de passe (min. 10 caractères).

11.5 Liste & suspension des super administrateurs

  • Liste : la page Super Admin affiche tous les comptes super administrateur (nom, email, statut, dernière connexion)
  • Suspendre / réactiver : bouton par ligne ; un compte suspendu ne peut plus se connecter ; chaque bascule est auditée (superadmin.user.toggled)
  • Garde : le dernier super administrateur actif ne peut pas être suspendu (message d'erreur) — évite de verrouiller la plateforme
  • Un utilisateur non-super-admin n'est pas concerné par ces actions (404)
Le super administrateur n'a pas, par défaut, accès au contenu des tenants (RM-003).
