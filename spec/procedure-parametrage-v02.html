Procédure de paramétrage — GED documentaire opérationnelle V02

Guide pas à pas pour reproduire le système documentaire décrit dans « GED documentaire opérationnelle V02 » sur la plateforme Open-CoolGed (ex-Kaeged).

Document source : spécification V02 client (document non hébergé dans le dépôt) — cible retenue : application Laravel Open-CoolGed (les points spécifiques à Odoo sont hors périmètre).

2. Paramétrage pas à pas

2.0 Ordre recommandé

Suivre cet ordre garantit que chaque étape dispose des données nécessaires :

  1. Créer les sections (espaces) et lots (dossiers) — structure d'arborescence
  2. Vérifier/ajouter les familles documentaires (types)
  3. Créer les référentiels (domaines, processus, postes, sites, entités, pays)
  4. Compléter les métadonnées (26 colonnes du registre)
  5. Paramétrer les droits d'accès (rôles, groupes, rôles de groupe)
  6. Configurer le workflow de validation
  7. Activer les options (accusés de lecture, alertes, partage)
  8. Importer le registre (ou créer les fiches manuellement)
1Créer les sections (espaces)
Menu : Espaces → « Espace »

Chaque section validée du registre devient un espace :

Code sectionNom de l'espace à créer
0000 - Gouvernance documentaire
0101 - Gouvernance Groupe et juridique
0202 - Stratégie Groupe, pilotage et performance
0303 - Organisation Groupe, responsabilités et délégations
0404 - Management des risques, contrôle interne et conformité

Mode opératoire : Espaces → « Nouvel espace » → saisir le nom → optionnellement une description et une couleur → « Créer ». Répéter pour chaque section.

2Créer les lots (dossiers) dans chaque section
Menu : Espaces → (espace) → « Nouveau dossier »

Exemple : dans « 00 - Gouvernance documentaire », créer le dossier « Lot 00 - Gouvernance documentaire ». Les dossiers peuvent être imbriqués (sous-dossiers) selon l'évolution du registre.

Le classement par lot est paramétrable : d'autres lots peuvent être ajoutés au sein d'une section sans impact sur l'existant.
3Vérifier les familles documentaires (types)
Administration → Types & métadonnées

Le seeder crée les 15 familles V02. Vérifier leur présence :

POL - Politique, MAN - Manuel, REF - Référentiel, PRO - Processus, PRC - Procédure, INS - Instruction, FOR - Formulaire, REG - Registre, MOD - Modèle, RAP - Rapport, PRE - Preuve, MAT - Matrice, TDB - Tableau de bord, CHK - Checklist, AUT - Autre

Mode opératoire : Types & métadonnées → « Nouveau type documentaire » → nom au format « CODE - Nom » → rétention éventuelle (jours) → « Créer ».

La famille AUT - Autre doit rester exceptionnelle et contrôlée par l'administrateur GED.
4Créer les référentiels
Administration → Référentiels (onglets par type)

Créer les listes de référence utilisées pour qualifier les documents et filtrer « Mes documents » :

Mode opératoire : choisir l'onglet du type → saisir nom (+ code optionnel) → « Ajouter ». Le dédoublonnage est automatique (insensible à la casse).

Ces référentiels serviront aussi à renseigner la fiche utilisateur (poste, département, direction, site, entité, pays) — indispensable pour le menu « Mes documents ».

6Paramétrer les droits d'accès
Administration → Rôles & permissions / Groupes / Utilisateurs

6.1 Rôles (profils V02)

Les rôles système couvrent les profils du document. Vérifier/adapter les permissions :

Profil V02Rôle Open-CoolGedPermissions clés
Créateur / Propriétaireuser / managercreate, edit (brouillon), comment
Vérificateurvalidatorview, preview, download, workflow.validate
Approbateurmanager / tenant_adminworkflow.approve, workflow.reject
Lecteuruser (lecture seule possible)view, preview (sans download si souhaité)
Auditeurauditorview, preview, admin.audit
Administrateur GEDtenant_admintoutes admin.*

Mode opératoire : Rôles & permissions → pour chaque rôle, cocher les permissions, choisir la portée (tenant / espace / dossier / document) et le refus explicite si besoin.

6.2 Groupes et rôles de groupe

Créer des groupes métier (Direction, Qualité, Achats…) et leur attacher des rôles : tous les membres héritent automatiquement des rôles du groupe.

Mode opératoire : Administration → Groupes → « Créer » → ajouter les membres → cocher les rôles dans « Rôles du groupe » → « Enregistrer les rôles ».

La colonne « Permissions effectives » de l'écran Utilisateurs permet de vérifier l'union des rôles directs et hérités.

6.3 Dimensions utilisateur (poste, département, site…)

Mode opératoire : Administration → Utilisateurs → « Modifier » → renseigner le poste, département, direction, site, entité, pays (référentiels créés à l'étape 4).

Ces dimensions pilotent le menu « Mes documents » : un utilisateur ne voit que les documents liés à ses dimensions ou à ses rôles de propriétaire/vérificateur/approbateur.
7Configurer le workflow de validation
Menu : Workflows → « Nouveau workflow »

Modéliser le circuit V02 (7 statuts) avec les étapes de validation :

à créer → brouillon → en vérification → en approbation → approuvé/applicable
                                    ↘ (rejet) → brouillon
approuvé/applicable → en révision → (nouvelle version) → en vérification
approuvé/applicable → obsolète/archivé   (remplacement ou retrait)

Mode opératoire :

  1. Workflows → « Nouveau workflow » → nom (ex. « Validation des contrats ») → type documentaire associé (ex. PRC - Procédure)
  2. Ajouter les étapes : « Vérification » (assignée au rôle Validator), « Approbation » (assignée au rôle Manager ou tenant_admin)
  3. « Créer le workflow » puis l'activer

Règles de contrôle automatiques (§9.3 du document V02)

Avant le passage à « approuvé/applicable », le système vérifie :

  1. un fichier est attaché ;
  2. une version est renseignée ;
  3. un propriétaire est affecté ;
  4. une date d'application est fixée ;
  5. une prochaine date de revue est fixée.

Obsolescence automatique : une nouvelle version applicable rend l'ancienne obsolète/archivée (masquée aux utilisateurs standards, lien remplace/remplacé par).

3. Mise en pratique — scénarios

3.1 Créer et faire valider un document (parcours complet)

1Créer la fiche documentaire
Documents → Importer
  1. Titre officiel + référence (ID du registre) + code document (ex. KAE-DOC-POL-001)
  2. Section (espace) + Lot (dossier) + Famille (type documentaire)
  3. Champs V02 : domaine, processus, propriétaire, vérificateur, approbateur, criticité, dates
  4. Déposer le fichier (V01) → « Importer et créer » → statut « brouillon »
2Lancer le workflow
Fiche document → onglet Workflow → « Démarrer le workflow »

Le document passe « en vérification » ; le vérificateur reçoit une tâche.

3Vérifier puis approuver
Mes tâches (vérificateur puis approbateur)
  1. Le vérificateur ouvre la tâche, vérifie le document → « Valider » (ou « Rejeter » avec motif obligatoire)
  2. Le document passe « en approbation » ; l'approbateur valide
  3. Si toutes les règles §9.3 sont satisfaites → « approuvé/applicable » ; sinon, message listant les règles manquantes
Pour tester : créer d'abord un document sans propriétaire → l'approbation est bloquée avec le message « Un propriétaire doit être affecté… ».
4Vérifier dans « Mes documents »
Sidebar → Mes documents

Le document approuvé apparaît (version active, statut approuvé/applicable) pour les utilisateurs dont les dimensions correspondent. Badges « proche » (≤30 j) / « en retard » sur la prochaine revue.

3.2 Accusé de lecture

1Activer l'accusé sur un document
Fiche document → Métadonnées → case « Accusé de lecture requis »
2Accuser lecture
Mes documents → bouton « Accuser »

Le badge « lu » remplace le bouton ; l'événement est tracé dans l'audit (v02.read_acknowledged).

3.3 Nouvelle version et obsolescence

1Passer en révision
Fiche document → Workflow

Le propriétaire/administrateur lance une révision → statut « en révision ».

2Créer la nouvelle version
Fiche document → onglet Versions → « Créer une version »

Version V02 (ou V01.1 mineure avec « [mineur] » dans le commentaire) → relancer le workflow.

3Constater l'obsolescence automatique

À l'approbation de la nouvelle version : l'ancienne passe « obsolète/archivé », masquée aux standards, avec lien « remplacé par ». L'audit trace l'événement.

4. Import du registre maître (optionnel)

4.1 Préparer le fichier CSV

13 colonnes, séparateur point-virgule ;, en-tête obligatoire :

id;code;titre;section;lot;famille;version;statut;proprietaire;date_application;prochaine_revue;domaine;criticite
001;KAE-DOC-POL-001;Politique de gouvernance documentaire;00 - Gouvernance;Lot 00;POL;V01;approuve_applicable;;2026-01-01;2027-01-01;GOV;critical
ColonneContrainte
idobligatoire, unique
codeobligatoire, unique (ex. KAE-DOC-POL-001)
titreobligatoire
section / lotcréés automatiquement si absents
famillecréée automatiquement si absente
versionobligatoire (V01, V02…)
statutune des 7 valeurs : a_creer, brouillon, en_verification, en_approbation, approuve_applicable, en_revision, obsolete_archive
proprietairenom d'un utilisateur existant du tenant
date_application / prochaine_revueformat AAAA-MM-JJ
domaine / criticiteréférentiel / standard, important, critical

4.2 Lancer l'import

# À exécuter à la racine du projet applicatif (SSH ou terminal local)
php artisan v02:import registre.csv --tenant=1 --dry-run   # simulation
php artisan v02:import registre.csv --tenant=1             # exécution

Le rapport affiche : nombre de documents créés, référentiels créés, erreurs ligne par ligne (doublons, statuts invalides, colonnes manquantes rejetés sans création).

4.3 Contrôles qualité avant import (recommandés)

  • Nettoyer les doublons d'ID et de codes documents
  • Harmoniser les libellés des sections/lots/familles
  • Valider les statuts et versions
  • Vérifier que les propriétaires correspondent à des utilisateurs existants

5.3 Pièges fréquents

Document non approuvable : vérifier propriétaire, date d'application et prochaine revue (règles §9.3).
Document invisible dans « Mes documents » : vérifier le statut (approuvé/applicable), la version active et les dimensions de l'utilisateur (poste, département, site…) ou son rôle de propriétaire/vérificateur/approbateur.
Import rejeté : vérifier le nombre de colonnes (13), les codes uniques et les statuts (7 valeurs autorisées).
Règle de travail : toute évolution non prévue au cahier des charges doit être tracée dans docs/evolutions-cahier-des-charges.md.
